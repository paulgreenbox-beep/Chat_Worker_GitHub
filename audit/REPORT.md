## Fixed defects and interface changes

1. **Validation bypass through Deserialize:** public models previously derived unchecked deserialization, so valid JSON could produce wrong-schema, empty-ID/thread, zero-numeric-ID and oversized-body models. Private strict wire representations now convert through shared validation before exposing `Message`, `GithubSource` or `ChatTarget`. Direct Rust construction remains possible for compatibility; Router revalidates on admission. Raw duplicate/unknown-field rejection was preserved and tested, not weakened.
2. **Incomplete identity syntax:** GOAL checked only its prefix, repository names admitted invalid owners/path components, and provider content was not constrained. Shared documented validation now bounds and checks these fields. Numeric zero uses `InvalidMessage::Identity`; syntax, sizes and schema retain distinct classes. Errors implement Display/Error without echoing message text.
3. **Invalid binding registration:** `register` previously checked only three nonempty strings. It now calls the same repository/GOAL/target validator used for message admission. This is syntax validation, not owner authorization.
4. **Repository case aliases:** binding and comment deduplication keys used case-sensitive names. They now canonicalize ASCII GitHub owner/name components together, so case variants cannot register a second route or bypass replay history. Provider/thread/GOAL values remain exact and case-sensitive.
5. **Premature ACK and missing modeled transitions:** ACK previously accepted DELIVERING; DELIVERED/COMPLETED/UNKNOWN-to-BLOCKED had no public transitions despite the architecture diagram. Added `mark_delivered`, `complete`, `block_unknown` and a single guarded transition primitive. ACK now requires DELIVERED. Wrong-state/missing-ID calls never change state; UNKNOWN cannot return to a retryable state.
6. **Workspace hygiene:** formatted owned Rust files, committed Cargo.lock, and added source/evidence line-ending attributes. The original unit tests and all their assertions remain intact.

Public wire field names and status names remain the same. Deserialization and identifier grammars intentionally reject formerly accepted invalid input; callers must use the documented numeric GOAL suffix. Consumers that acknowledged directly from DELIVERING must now record independently observed provider acceptance first. New helper APIs are `ChatTarget::validate`, `GithubSource::validate`, `validate_binding` and `MAX_BODY_BYTES`; none authenticate a caller.

Covers all 10 requested negative categories: schema, empty message ID, repository, empty thread ID, GOAL, oversized body, unknown fields, duplicate fields, malformed Unicode and numeric IDs. Also covers standalone models, field bounds, valid Unicode/u64 boundaries, required/malformed/trailing JSON, status wire names and error classification. Each invalid constructed message is also serialized and then refused by typed raw-JSON deserialization.
- Router: 2 pre-fix regressions in [audit_regressions.rs](../CWG_Router/tests/audit_regressions.rs), plus 16 tests in [routing.rs](../CWG_Router/tests/routing.rs). Covers independent repositories, two logical Codex chats, simultaneous GOALs, repeated message/comment IDs, wrong thread/provider, unknown binding, missing message delivery, UNKNOWN replay refusal and every reachable state × every transition operation. Additional cases cover invalid registration, case aliases, immutable bindings, failed admission without partial dedupe insertion, competing in-memory claims under an external mutex, and untrusted body text not changing policy.
- Preserved originals: `rejects_empty_body`, `exact_binding_and_duplicate_refusal`, `uncertain_delivery_does_not_retry`. None was deleted, ignored, renamed or weakened.

The two-thread/claim tests use Rust threads and an external mutex around one Router. They prove only serialized local model behavior, **not Codex thread isolation, distributed claims or durable exactly-once delivery**.

## Security and architecture findings

| Boundary | Implemented / source evidence | Remaining requirement and result |
|---|---|---|
| Input / duplicate keys / Unicode | Shared validation; strict private wire structs; raw-JSON negative tests | Raw request must be size-limited before allocation. A generic map/Value loses duplicate keys before this model sees them. No receiver is implemented. |
| Source/actor ID spoofing | Nonzero u64 and valid repository syntax only | Caller identity, author permission and GitHub object existence cannot be established by these values. External authenticated ingress/API reconciliation required. |
| Repository / logical thread routing | Canonical repository + exact GOAL/provider/thread; immutable bindings; mismatch tests | Numeric repo ID, account scope, generations, revocation and stale-thread resolution are absent. Repository rename/recreation is not secured by name matching. |
| Registration authority | Invalid/repeated bindings refused; body never parsed as policy | Any in-process caller with Router access can call register. Owner approval is a caller precondition; no fake authorization flag was added. |
| Replay / collisions | Per-instance global message ID and canonical repo/comment dedupe; failure atomicity tests | State is lost on restart. Trusted ingress must allocate globally unique message IDs to prevent cross-repository collision denial. Webhook delivery IDs are not stored yet. |
| Races / recovery | Exclusive mutable access; guarded claims; one winner under external mutex | No durable store, multiprocess locking, crash recovery, queue capacity/retention or distributed atomicity. |
| States / UNKNOWN | Exact modeled transitions; no blind retry; UNKNOWN can only be blocked | Status APIs record the trusted controller's claims; they do not verify real acceptance, receipts, work evidence or owner review. |
| Untrusted GitHub content | Router stores body as data; no model/shell/network calls | Future provider must preserve the trusted/untrusted boundary and separately authorize delivery/publication. |
| Local source / dependencies | Both libraries forbid unsafe; no unsafe block/function found in owned Rust sources; dependency graph/licenses recorded; targeted publication scan found no credential/private-host-path candidates | This does not certify every transitive dependency's implementation or establish absence of every possible secret. Advisory database scan NOT_RUN; no extra executable installed. |

# Verification matrix

PASS means the named check actually ran and met its assertion on the recorded source/platform. FAIL means an executed check failed. NOT_RUN means no execution evidence exists. These results cover different boundaries; compilation, unit/model checks, source review, actual delivery and release acceptance are not interchangeable.

CHEAPEST_VERIFICATION_PATH: for Protocol edits, `cargo test -p cwg-protocol`; for Router edits, `cargo test -p cwg-router`; for audit tooling, Node's builtin test runner against the owned audit tests. Final acceptance runs the seven workspace gates requested by the owner in order, followed by a locked/offline test and `git diff --check`. See [audit logs](../audit/evidence/), [security follow-up](../audit/SECURITY_REVIEW.md) and [historical report](../audit/REPORT.md).

`serde_json` is now a Protocol runtime dependency for the bounded raw JSON decoder as well as its format tests. This reuses version 1.0.154 and its existing locked transitive dependencies; the security justification is enforcing a raw-byte bound before entering the parser. No registry versions were upgraded. `.gitattributes` keeps source line endings stable and preserves exact evidence bytes across checkouts. No new toolchain or executable is installed by the audit.

Run `node audit/verify.mjs final-3` (or a fresh final-N name) to record the exact seven Cargo gates with command/exit code/test totals and redacted host paths. Attempt directories are reserved atomically; any existing/partial attempt is refused and files are written exclusively. Source inventory, hashes, HEAD and selected environment fingerprints are compared before/after; observed drift makes the attempt fail even if Cargo commands returned zero. Relevant compiler/config/script inputs are included, but this is not proof of a hermetic host or absence of temporary changes that were restored between observations.

Node is optional audit tooling, not a Rust/runtime dependency. Run `node audit/review.mjs review-2` (or a fresh review-N name) for a locked/offline dependency graph and targeted publication scan; each report gets a fresh attempt directory and existing paths are refused. Historical evidence is preserved. Logs contain real command output with workspace/home paths redacted, including Windows case and JSON-escaped variants; summary SHA-256 values cover the published bytes. A targeted scan is not a package advisory database audit. Test fixtures remain ignored under `audit/.scratch/` and are not publication artifacts.

If a transcript contains trailing whitespace (for example a failing rustfmt diff), its `.txt` artifact contains a lossless JSON envelope with a `transcript` string. Decode that string to recover every redacted transcript byte. `transcript_sha256` covers the decoded transcript; `log_sha256` covers the published envelope. This changes the encoding only; original FAIL results and diagnostic whitespace are preserved.
